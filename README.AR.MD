# Galaxy S24 — SM-S921B (e1s)

[English](README.md)

نواة سامسونج DZG1 مع [BakaSU](https://github.com/Baka-SU/BakaSU) (المعروف سابقًا باسم ReSukiSU) وSuSFS، تُبنى باستخدام هدف سامسونج في Bazel/Kleaf.

نجح البناء وفحص الحزم محليًا، ونجح بناء حزم النواة ونشرها عبر GitHub Actions أيضًا. اختُبر البناء على SM-S921B بروم `S921BXXSGDZG1` في 2 نوفمبر 2026، ونجحت اختبارات الإقلاع والروت وpreinit ودورة الموديول.
مصدر النواة وحزم الأدوات متوفرة في إصدار `build-inputs-v1`. البناء التلقائي مفعّل في هذا المستودع؛ النسخ المتفرعة تحتاج إلى تفعيله في إعداداتها.

## البناء

المتطلبات: Linux x86_64، وPython 3.12 أو أحدث، وGit، وcurl، وtar، وzstd، وzip، وunzip، وmake، وutil-linux، وcoreutils. وفّر نحو 100 GiB من المساحة الحرة.

```bash
git clone https://github.com/NawafCode/Galaxy-S24-SM-S921B-e1s-Kernel.git
cd Galaxy-S24-SM-S921B-e1s-Kernel
./build.sh
```

أمر واحد ينزّل المدخلات ويتحقق منها، ويدمج الروت، ويبني النواة ويغلّفها. لا يفلش الهاتف أو ينشر الملفات.

- `./build.sh --prepare`: تجهيز المصدر والأدوات فقط.
- `./build.sh --config`: تجهيز إعدادات النواة.
- `./build.sh --build`: البناء والتغليف، وهو الخيار الافتراضي.
- `./build.sh --package`: إعادة تغليف آخر بناء ناجح.
- `./build.sh --help`: عرض الخيارات المتاحة.

## المخرجات

مجلد `release/` يحتوي AnyKernel3 ZIP و`boot.img` و`boot.img.tar`.

```text
Nawaf-e1s-Kernel-<KERNEL_VERSION>-android<ANDROID_VERSION>-Nawaf-BakaSU-<SHA7>-SuSFS-<YYYYMMDD-HHMM>.zip
```

اسم ZIP يستخدم إصدار النواة المبنية، وفرع Android للمصدر، وSHA الروت التي تم التحقق منها، ووقت البناء بتوقيت UTC. إعادة التغليف تحفظ الاسم والتوقيت.

## المدخلات

- مصدر سامسونج وحزم الأدوات: من إصدار `build-inputs-v1` في هذا المستودع، مع فحص بصمات SHA-256.
- BakaSU: أحدث commit في الفرع الافتراضي عند بدء كل بناء، يُفحص ويثبت طوال التشغيل. يتوقف البناء إذا فشل فحص المستودع. إعادة التغليف تستخدم النسخة المحفوظة.
- SuSFS وAnyKernel3: نسخ مثبتة في `config/inputs.env`.

ملف Magisk APK يوفر أدوات المثبت بنسخة ARM64 فقط؛ الروت هو BakaSU. التراخيص الأصلية مرفقة بحزم المصدر والأدوات.

يدعم المنبع الآن تطبيقات BakaSU وKernelSU الرسمي وKOWSU. أزيل الدعم المدمج لتطبيقات MKSU وRKSU وSukiSU-Ultra. هذا المستودع لا يبني تطبيق Manager ولا يرفقه بالحزم.

إعدادات النواة في `config/root.config` والباتشات في `patches/`. راجع إعدادات صورة الإقلاع في `config/inputs.env` عند تغيير الروم.

### تحديث دمج الروت — نوفمبر 2026

يستهدف الدمج BakaSU عند `516d3e87fbc986ccefdde2c2765f1700612441a9` وSuSFS عند `0d5b1ceb4ca4cddbe59d04233f4425a83030aa71` من فرع `gki-android14-6.1`. يستمر البناء في جلب أحدث commit من BakaSU، ويشترط نجاح تطبيق باتش التوافق المحلي عليه. ما زال SuSFS يعرض `v2.3.0`، لذلك تُستخدم SHA الكاملة لتمييز هذا التحديث.

- يتبع `patches/susfs.patch` باتش المنبع المختار، بما يشمل preinit ودمج SELinux الجديد، مع تكييف سياق الترويسات لسامسونج.
- يربط `patches/bakasu-susfs.patch` تعديلات سياسات BakaSU بتتبّع SELinux في SuSFS، ويضيف أمر مرشح التطبيقات وتحديثه عند تغيّر الحزم. تُسجل قواعد الوصول فقط، دون أقنعة التدقيق.
- يصلح `patches/susfs-types.patch` تصادمات جدول أنواع SELinux المخفية، حتى لا يخفي نوعًا أصليًا غير مرتبط لمجرد وجوده في الخانة نفسها.
- يربط `patches/module-blacklist.patch` استدعاءَي تحميل وحدات النواة بميزة الحظر في BakaSU. يعيد باتش توافق BakaSU أيضًا تسمية مؤشره الداخلي لمنع تصادم اسمه مع رمز `module_blacklist` الخاص بمحمّل النواة، ويتحقق البناء من وجود رمز أصلي وحيد. لم تُضبط قائمة لحظر تعريفات أي شركة.
- يوفر `CONFIG_HEADERS_INSTALL=y` ترويسات UAPI لبناء برنامج preinit المضمّن لمعمارية ARM64. تفحص مرحلة التحقق بايتاته داخل `Image` ورموز الدمج وإعدادات النواة قبل التغليف.

تسجل بيانات البناء SHA المنبع وشجرة Git الخاصة بـBakaSU بعد الباتش وبصمات الباتشات وإصدار UAPI وبصمة برنامج preinit. تحتوي نسخة الروت المدمجة تغييرات staged مقصودة؛ وتُفحص شجرتها وملفاتها قبل الترجمة وبعدها. لذلك يتضمن إصدار BakaSU اللاحقة `-dirty` بسبب الباتش المحلي الموثّق. تبقى نسخة المنبع القابلة لإعادة الاستخدام نظيفة.

تحتاج ميزات UAPI v6 وpreinit والتثبيت دون إعادة تشغيل إلى Manager و`ksud` من نسخة BakaSU المختارة أو نسخة أحدث متوافقة. يتطلب التثبيت دون إعادة تشغيل دعم الموديول أيضًا. يحتاج مرشح التطبيقات إلى أداة/موديول `ksu_susfs` المحدّث من نسخة SuSFS المختارة. لا تُرفق هذه المكونات بحزم النواة.

تبقى `shell_su_adb_only` ميزة اختيارية. الروت مدمج في النواة (`CONFIG_KSU=y`)، لذلك يستخدم فرض قيم الميزات معاملات الإقلاع مثل `kernelsu.force_feature=shell_su_adb_only:1`؛ أما آلية `/ksu_config` في ramdisk بالمنبع فتخص محمّل وحدة الروت. لا يفرض المشروع قيمًا للميزات أو معاملات إقلاع جديدة.

نجح التحقق المحلي في 1 نوفمبر 2026: البناء الكامل بهدف سامسونج، والاختبارات الثمانية، وإعادة تغليف الحزم الثلاث ببايتات مطابقة دون نسخة احتياطية إضافية. أشارت تحذيرات `depmod` أثناء تجهيز الموديولات إلى 87 رمزًا مختلفًا؛ جميعها موجودة في ملف `Module.symvers` المجمّع.

نجحت أيضًا عشرة فحوص محلية لتطبيق الاختبار وحزم الموديول قبل تجربتها على الهاتف. في 2 نوفمبر 2026 نجحت اختبارات رفض الروت ومنحه وسحبه، والتثبيت والتعطيل وإعادة التفعيل والإزالة، وpreinit والتحديث الفوري. اكتملت خمس إعادات تشغيل مع SELinux بحالة Enforcing بعد كل إقلاع، ثم أُزيلت مكونات الاختبار من الهاتف.

تخص النتائج البناء المختبر وموديولًا تجريبيًا لتشغيل السكربتات. ما زالت اختبارات تركيب الملفات وتحميل وحدات النواة `.ko` ومرشح UID وإخفاء SELinux ووظائف الهاتف والبطارية والحرارة والاستقرار الطويل تحتاج فحوصًا مستقلة.

الاختبارات وسجلات الهاتف محفوظة محليًا في مسارات مستثناة من Git. تسجل مرحلة البناء `hardware_boot_verified=false` لأنها تفحص مخرجات البناء فقط؛ نتائج الهاتف موثقة بصورة منفصلة.

## تنظيم الكود

`build.sh` هو نقطة الدخول. يدير التنزيلات والتحقق من النسخ والقفل والسجلات ودمج الروت وتشغيل Bazel/Kleaf. تحتفظ ثلاثة ملفات Python بمنطق التجهيز والتحقق والتغليف الموجود:

| الملف | المسؤولية |
| --- | --- |
| `scripts/prepare.py` | استخراج مصدر سامسونج وتعديل تعريف البناء |
| `scripts/verify_kernel.py` | فحص النواة المبنية وحفظ بيانات البناء |
| `scripts/package.py` | إنشاء الحزم الثلاث والتحقق منها |

تبقى الإعدادات في `config/` والباتشات في `patches/`. أي تعديل على ملفات Python يؤثر في `BUILD_KEY`، لمنع إعادة استخدام مساحة عمل أو بيانات غير متوافقة. لم يُحدّد ترخيص `LICENSE` للمشروع بعد؛ تراخيص المكونات الأصلية تبقى خاصة بها.

## البناء التلقائي

يشغّل `.github/workflows/build.yml` سكربت البناء نفسه على GitHub Actions. يفحص BakaSU كل ست ساعات، وعند تغييرات البناء على `main`، أو يدويًا من **Run workflow**. يتخطى البناء المنشور مسبقًا بنفس مفتاح البناء، ويثبت SHA الكامل بين التجهيز والترجمة.

للتفعيل في مستودع جديد:

1. ارفع حزم المدخلات الخمس في إصدار `build-inputs-v1` دون جعله Latest، وتأكد من روابطها وhashes في `config/`.
2. من **Settings → Secrets and variables → Actions → Variables** أضف `ENABLE_KERNEL_CI` بالقيمة `true`.
3. شغّل **Build e1s kernel** يدويًا وراجع النتائج. تفعيل المتغير يفعّل أيضًا الجدولة والتشغيل عند الدفع، وكل تشغيل ناجح ينشر تلقائيًا.

الجهاز الافتراضي `ubuntu-24.04`. يحذف workflow مجلدات SDK غير المستخدمة الخاصة بـAndroid و.NET وGHC وBoost على أجهزة GitHub المستضافة، ثم يشترط 60 GiB فارغة. عند فشل الفحص، اضبط متغير `KERNEL_RUNNER` على اسم جهاز Linux x64 مناسب متاح للمستودع. الأجهزة الأكبر قد تكون مدفوعة. تختلف مدة البناء واستهلاك الموارد بحسب المدخلات والجهاز.

يحفظ الكاش حزم المدخلات المضغوطة فقط. استعادتها تتطلب نقل بيانات وفك الضغط مجددًا، وتبقى فحوص SHA-256 إلزامية. عند غياب الكاش تُنزّل الحزم من إصدار المدخلات. لم نضف كاش لنتائج الترجمة.

مهمة نشر النواة فقط تملك صلاحية الكتابة. تتحقق من hashes، وترفع الحزم الثلاث إلى مسودة، ثم تنزّلها وتتحقق منها قبل نشرها كـLatest. فشل البناء يبقي الإصدار السابق متاحًا. تبقى metadata والسجلات في Actions artifacts وليست ضمن ملفات الإصدار العامة.

إذا فشل النشر بعد حفظ الحزم، استخدم **Re-run failed jobs** خلال فترة الاحتفاظ البالغة 14 يومًا لإعادة النشر دون ترجمة جديدة. التشغيل الجديد لا يستعيد تلقائيًا artifacts من تشغيل أقدم. قد يعاد البناء الفاشل مع المشغّل التالي؛ منع التكرار يخص الأبنية الناجحة المنشورة. قد تتأخر الجدولة على GitHub.

يتولى `scripts/ci.py` قرار البناء والتحقق والنشر باستخدام مكتبة Python القياسية وGitHub CLI المتوفر على الجهاز المستضاف. تمرير commit داخلي ومخصص لـActions؛ البناء المحلي يظل يجلب أحدث commit بنفسه. احتُفظ بأسماء حقول البيانات ومسارات الكاش القديمة، ويمكن لـCI قراءة ملاحظات إصدارات ReSukiSU وBakaSU. لا يقوم المشروع بالتفليش التلقائي.

### متى يعاد بناء النواة

يقارن CI أحدث commit في BakaSU بآخر نواة منشورة. إذا لم تتغير مدخلات مشروعنا واقتصرت المقارنة الكاملة على `manager/` أو `docs/`، يحتفظ بالنواة الحالية. أي تغيير خارجها أو نقل ملف من النواة أو تاريخ متفرع أو مقارنة غير مكتملة يؤدي إلى البناء. لا نعيد البناء لمجرد تغير رقم الإصدار المحسوب من Git عند تحديث المدير أو الشروحات؛ تحتفظ النواة المنشورة بـSHA وإصدار بنائها الحقيقيين. أمر `./build.sh` المحلي يظل يبني أحدث commit.
